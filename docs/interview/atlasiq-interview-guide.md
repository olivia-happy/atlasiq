# AtlasIQ 面试讲解稿

## 60 秒项目介绍

AtlasIQ 是一个面向新能源出海团队的本地优先市场研究与决策协作工具，我以德国光伏进入研究作为案例。它解决的不是“找不到数据”，而是公开数据、新闻、模型结论和人工决策彼此割裂的问题。

系统把四类能力放在一条可审计链路中：第一，后端用透明加权评分、情景模拟、蒙特卡洛区间和单变量敏感性分析负责计算；第二，AI 只根据服务端已筛选的证据和指标生成流式研究简报；第三，用户保存人工决策并设置复盘日期；第四，已确认的市场信号会基于共享证据维度提醒复盘，但不会自动改写结论。

我使用 React + TypeScript 和 FastAPI 实现前后端，默认 SQLite 零成本运行，同时预留 PostgreSQL、Redis、Docker 和本地 Ollama 的生产化接口。项目重点是把统计、产品闭环和工程可解释性结合起来，而不是做一个聊天机器人外壳。

## 简历表述

- 独立设计并实现 AtlasIQ 本地优先 AI 市场研究平台，使用 React、TypeScript、FastAPI、SQLAlchemy 和 SSE 串联公开数据、可解释评分、AI 研究和人工决策复盘。
- 构建透明市场评分、固定随机种子蒙特卡洛模拟（P10/P50/P90）和单变量敏感性分析，量化补贴、需求、并网风险、资源条件对市场优先级的影响。
- 设计“研究 → 决策卡 → 到期/信号触发复盘 → 人工复盘记录 → Markdown 简报”的闭环；已确认新闻仅触发人工核验，不自动修改评分或决策。
- 实现本地 Ollama SSE 调用与确定性降级、运行审计（P50/P95、降级率、证据覆盖率）、公开 RSS 去重持久化和零云成本本地一键验证脚本。

## 3 分钟 Demo 讲法

### 0:00–0:35：先讲问题与边界

“海外市场进入研究通常有三个断点：数据很分散、AI 结论难追溯、研究结束后没有人回看原假设。AtlasIQ 不做自动投资决策，而是把数据、AI、人工判断和复盘放进同一个工作流。”

### 0:35–1:15：展示统计层

打开市场总览，说明机会评分由增长、资源、政策、需求/电网四项及权重构成。将补贴变化调至 -20%，运行模拟：

- 用情景结果展示具体假设的方向性影响；
- 用 P10/P50/P90 展示不确定性，不把单点分数伪装成确定预测；
- 用敏感性排序说明下一步应优先验证需求还是并网风险。

一句话收束：“模型告诉我先查哪里，不替我做市场进入决定。”

### 1:15–1:55：展示 AI 真实价值

在 AI 研究区问“主要风险是什么”。展示流式输出、证据编号、模式和耗时。

“AI 在这里负责把后端已验证的数据和证据组织成面向业务的简报；它不能直接写 SQL，也不能凭空改变评分。Ollama 不可用时，系统返回带证据的确定性降级结果，保证演示和审计不断链。”

### 1:55–2:35：展示产品闭环

保存为决策卡并设置复盘日期，展示逾期/今日/未来 7 天队列。确认一条中高优先级市场信号，说明它只在共享证据维度时提醒复盘相关卡片。

“新闻不是指令。它先由分析师确认，再成为需要重新验证假设的触发器。”

### 2:35–3:00：展示最终交付

在卡片上记录“维持、调整或终止跟踪”的人工复盘结果，随后导出 Markdown 简报。

“这样系统的最终产物不是一次聊天记录，而是一份能同步给团队、能在未来回看的决策文档。”

## 为什么这里必须使用 AI

| 问题 | 不用 AI 的方式 | AtlasIQ 中 AI 的职责 |
| --- | --- | --- |
| 多源指标与政策/新闻证据难以面向业务表达 | 分析师手动复制数据写周报，慢且格式不稳定 | 基于受控指标与证据流式生成结构化研究简报 |
| AI 幻觉可能污染决策 | 让模型直接联网搜索或查询数据库 | 服务端先选定证据；模型只接收该上下文，输出保留证据编号 |
| 本地模型可能不可用或慢 | 用户只能等待或界面报错 | 本地 Ollama + 可审计运行记录 + 确定性降级，保障核心工作流连续 |

评分、模拟、敏感性分析仍由确定性统计模块完成；AI 不能替代这些计算。

## 高频技术追问

### 为什么同时做蒙特卡洛和敏感性分析？

两者回答不同问题。蒙特卡洛在多个组件的不确定性假设下抽样，输出 P10/P50/P90 和达到阈值的比例，用于表达总体稳健性。单变量敏感性分析在其余变量固定时逐项扰动，输出排序，用于安排下一步尽调优先级。前者回答“结果有多不确定”，后者回答“先验证什么”。

### AI 结果为什么可信？

不把“可信”理解成模型永远正确。系统限制输入：AI 只看到服务端筛选出的指标、评分和证据；输出保留证据编号；运行模式、模型名、延迟和证据覆盖率持久化。任何结论仍必须由分析师确认，因此可信性来自可追溯工作流而不是模型宣称。

### SSE 如何保证前端体验？

后端通过 SSE 分阶段发送状态、文本 token、引用证据和完成事件；前端读取 `ReadableStream` 并解析事件块，逐步更新界面而非等待整段回答。若请求失败，界面显示明确错误；Ollama 不可用时后端走确定性降级而不是无限重试。

### 新闻如何避免重复推送与脏数据？

RSS 条目以稳定 ID 和 URL 去重后写入本地数据库。新事件先按规则分类，再匹配订阅阈值；确认状态也持久化。新闻信号不会直接改变评分，而是要求人工确认后才可能触发关联复盘。

### 多人并发更新决策卡怎么办？

当前本地演示默认 SQLite，适合单机。生产环境会切换到 PostgreSQL，并为决策卡增加版本号或 `updated_at` 条件更新，使用乐观锁避免覆盖；复盘记录采用 append-only 事件表，天然比覆盖原决策更易审计。

### Redis 在项目中解决什么？

市场总览适合短 TTL 缓存，避免高频读取时重复计算或重复访问公开数据。缓存不可用时回退到实时计算，保证功能可用。它不是数据正确性的唯一来源，数据库仍保存需要审计的事件。

### 如果数据源故障怎么办？

每个公开源保留最近检查时间、最近成功时间和观测范围。刷新失败时明确标记降级并保留已有信息，不伪造“实时”数据。对外展示时应说明当前数据的时效边界。

## 生产化演进

- PostgreSQL 上使用迁移工具管理 schema，并为决策编辑加入乐观锁。
- 采用队列和独立 worker 承担 RSS 拉取、邮件投递和长时 AI 任务；为每个任务增加幂等键和重试策略。
- 对本地/远程模型分别设定超时、并发上限、熔断和成本预算；继续保留可审计降级。
- 增加 RBAC、审计日志脱敏、速率限制、指标监控和告警。

## 诚实表述边界

- 德国市场数据当前是公开数据接入结构与演示种子的组合，不应描述为实时投资研究报告。
- AtlasIQ 不提供投资建议，也不执行自动市场进入决策。
- 项目默认不启用付费 API 或付费云服务；SMTP、Ollama、PostgreSQL、Redis 都是可选本地能力。
